# M3.0 multi-platform downloader audit

Audit date: 2026-11-01. Reference snapshot: `JustinNguyen9979/YTDown` commit `c6e6955`.

## Comparison

| Capability | YTDown evidence | ND current | Gap / action |
|---|---|---|---|
| Video extraction | `downloader.go` invokes yt-dlp with `--no-playlist`; XHS has a specialized fallback | `src-tauri/src/download.rs` invokes the centralized yt-dlp resolver and does not whitelist hostnames | Keep the generic extractor path; do not copy brittle XHS HTML handlers |
| Quality | YTDown uses `bestvideo*+bestaudio/best` for its best path and ranks metadata | ND now exposes `Best Available`, real source variants, and keeps MP4/WebM remux selection explicit | Implemented in ND selector construction |
| Playlist | YTDown has playlist-related options in the broader app, but the inspected downloader path defaults to `--no-playlist` | ND defaults to single media; playlist inspection/download requires an explicit checkbox and optional item list | Implemented; collection UX remains intentionally small |
| Browser auth | YTDown detects browsers and can export/copy cookies; README presents this as a dependency feature | ND only passes `--cookies-from-browser` after an explicit browser choice; no automatic cookie scan | ND behavior retained for least privilege |
| Image galleries | YTDown has a gallery-dl integration plus Xiaohongshu-specific handlers | ND has a gallery-dl command path through `BinaryKind::GalleryDl`, but no approved bundled gallery-dl binary | Implemented guarded workflow; unavailable runtime is reported explicitly |
| Runtime distribution | YTDown README describes Homebrew/APT/Winget dependencies; the repository snapshot has no `LICENSE` file despite its README saying MIT | ND uses the M2.7 resolver, pinned FFmpeg/FFprobe and managed update architecture | No YTDown source was copied; gallery-dl provenance remains a release blocker |

The YTDown README is treated as a product claim only. The table above is based on the implementation files, not README claims. Its gallery and XHS code is useful as an audit reference, but it is not copied into ND because it mixes app-specific cookie/export state, platform code and source-specific handlers.

## Routing and safety decisions

- HTTP(S) URLs are accepted without a hard-coded social-platform list.
- `--no-playlist` remains the default. `--flat-playlist --playlist-end 1` is used only after the user opts into collection inspection.
- Localhost, loopback, private/link-local IP literals, `.local`, `.internal` and unspecified addresses are rejected before yt-dlp/gallery-dl is started. DNS rebinding and extractor-level redirects still need a later sandboxed network boundary.
- Gallery downloads are explicit through the Image / gallery action. The command resolves `gallery-dl` through the existing runtime manager and never installs a global Python/Homebrew dependency.
- Browser cookie access remains opt-in and diagnostics are sanitized before being returned to the UI.

## Runtime status on this workspace

The production FFmpeg/FFprobe sources from M2.7 are unchanged. `gallery-dl` is represented by the runtime resolver and diagnostics, but is not bundled or pinned in `scripts/runtime-sources.json`; therefore the packaged app must report gallery support as unavailable until a trusted, per-platform artifact, checksum and license record are approved.

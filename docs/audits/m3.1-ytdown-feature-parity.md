# M3.1 YTDown feature-parity audit

Audit date: 2026-11-01. YTDown snapshot: `c6e6955`.

## Licensing and reuse

- The inspected [YTDown snapshot](https://github.com/JustinNguyen9979/YTDown) contains a README claim of MIT licensing, but no `LICENSE` file was present in the checkout. Its implementation is therefore treated as reference behavior, not copyable source.
- No YTDown Go/Wails module was copied into ND. ND reimplements the required behavior in Rust/Tauri and calls external tools through documented command interfaces.
- gallery-dl is GPL-2.0-only ([upstream license](https://github.com/mikf/gallery-dl/blob/master/LICENSE)). The [official download page](https://gallery-dl.com/download/) and [v1.32.19 release](https://codeberg.org/mikf/gallery-dl/releases/tag/v1.32.19) provide the Windows x64 executable and checksums; no official native macOS binary was found, so macOS remains blocked rather than using Python/Homebrew or an unverified build.

## Feature matrix

| Feature | YTDown implementation | ND implementation | Gap | Approach / status |
|---|---|---|---|---|
| Video/audio extraction | `downloader.go` calls yt-dlp and uses best selectors | Generic yt-dlp resolver, source-independent URL analysis | Live platform coverage varies with extractor/site state | Reimplemented; Best Available and audio-only are present |
| Metadata and quality | Parses yt-dlp format metadata and ranks quality | Rust parser exposes real variants, container, height, audio-only and estimated size | Codec detail UI is still intentionally compact | Implemented |
| Playlists | App-level playlist options; downloader path defaults to `--no-playlist` | Explicit playlist inspection, item metadata, checkbox selection and selected-item queue inputs | Full virtualized list and exact per-item extraction remain next work | Partially implemented |
| Gallery downloads | `gallery.go` invokes gallery-dl; XHS has a special handler | Central `BinaryKind::GalleryDl` resolver, gallery metadata command, selected index filter and output folder actions | macOS gallery runtime still blocked | Implemented where runtime exists |
| Browser auth | Browser detection/cookie export with Wails-specific state | Explicit `Sign-in (optional)` and allowlisted `--cookies-from-browser` only | No automatic browser discovery | Intentionally safer reimplementation |
| Progress | Wails events parse gallery/video output | Tauri `download-progress` events for video/gallery, persisted per-job status | gallery-dl count progress depends on extractor output and may remain indeterminate | Implemented; video uses structured progress, gallery uses count when available |
| Retry/cancel | App-specific command/process handling | Job-scoped cancellation, process-tree termination and explicit error classification | Native process-tree behavior still needs packaged Windows/macOS validation | Implemented for queued downloads; retry/cancel actions are persisted |
| Filename/output safety | Creator folders, media manifest and collision reservation | Restricted yt-dlp filenames, playlist folder template, explicit output directory | Gallery per-file collision policy relies on gallery-dl | Implemented/partially delegated |
| Updates/dependencies | Homebrew/APT/Winget installers and app update code | Signed managed engine architecture; no system installer requirement | Wails window/package-manager code is not applicable | Kept ND architecture |
| Video to GIF/conversion | Separate compressor/conversion features | Existing FFmpeg/FFprobe pipeline | None targeted by M3.1 | Preserved |

## Security implications

- YTDown cookie/profile logic is not directly transferable to Tauri and would expand secret-handling surface. ND keeps cookie access opt-in and never persists it in job metadata.
- External engine updates remain signature/checksum gated. gallery-dl source records fail closed when URL/hash/license data is absent.
- URL validation blocks local/private IP literals and local hostnames before either extractor starts. Redirect/DNS resolution still needs a stronger network sandbox for complete SSRF protection.

## Test requirements and status

- Deterministic Rust tests cover playlist mapping, gallery metadata records, selected gallery indices, Best Available, invalid/private URLs and auth argument construction.
- Live gallery-dl metadata extraction/download was previously verified with a public Wikipedia page using the same CLI contract; distributed-runtime verification is blocked on target packaging.
- Real social-site success is not inferred from extractor presence. Each platform needs an authorized fixture and must be reported as live, manual, blocked or not executed.

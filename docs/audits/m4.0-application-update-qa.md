# M4.0 application update and release QA audit

Date: 2026-11-01

## Implemented

- Stable and Beta application channels are persisted independently from Media Engine Updates.
- Release selection validates SemVer metadata, ignores drafts, handles GitHub prerelease flags separately from tag suffixes, and suppresses same application versions.
- Native Tauri target mapping remains authoritative for installer selection:
  - `aarch64-apple-darwin` → macOS ARM64
  - `x86_64-apple-darwin` → macOS Intel
  - `x86_64-pc-windows-msvc` → Windows x64
- Exact installer names and HTTPS GitHub release-download URLs are required. Missing platform assets open the release page and never select another architecture.
- About → App Updates provides installed version, channel, manual check, loading/error states, release notes, and user-initiated download handoff.
- Concurrent checks are deduplicated and stale panel responses are ignored.

## Integrity boundary

`SHA256SUMS.txt` is surfaced when present and the selected release URL is constrained to the repository's HTTPS GitHub release path. A public checksum verifies downloaded bytes only; it does not authenticate the publisher. No installer is silently downloaded or executed.

## Tauri updater readiness

The current application has no `tauri-plugin-updater`, updater public key, private signing key, static `latest.json`, or signed updater artifacts. The v0.9.0 pre-release therefore remains browser-assisted. A later build must add a separate Tauri updater keypair, protected CI private-key access, `createUpdaterArtifacts`, platform metadata, signature verification, progress, install/relaunch and recovery tests. The Media Engine Ed25519 key must not be reused.

## macOS signing gates

Production macOS distribution still requires credentials and CI configuration for:

- Developer ID Application certificate and Team ID.
- Hardened Runtime and entitlements.
- Nested signing for bundled FFmpeg, FFprobe, yt-dlp, gallery-dl, PO Token provider and companion libraries.
- Notarization submission, ticket polling and stapling.
- Final Gatekeeper validation on a clean supported macOS host.

The current workflow uses ad-hoc signing for bundled native dependencies only. It does not claim Developer ID signing or notarization, and no signed app contents may be modified after the future signing step.

## Windows signing gates

Production Windows distribution still requires a protected Authenticode certificate and identity, CI signing of the final NSIS installer, and `signtool verify /pa` validation. Signing may reduce SmartScreen friction but cannot guarantee that every warning disappears. The current v0.9.0 installer is unsigned.

## Website short link

`https://duongtruongdp.net/NDImgConverter_download` is a manually managed shortcut, not an update API. It currently redirects GET requests to the old v0.8.4 ZIP. The M4.0 source package does not modify WordPress or hosting. The explicit v0.9.0 pre-release URL remains the correct Beta destination until a website administrator deploys the prepared page or redirects the shortcut.

## Upgrade acceptance boundary

The archived v0.8.4 ARM64 DMG is available and was mounted read-only; its bundle reports version `0.8.4`. The historical artifact was not modified or installed over the working machine. A full v0.8.4 → v0.9.0 install, launch and settings-preservation test still requires an isolated clean macOS host/VM and must be run there before claiming end-to-end upgrade acceptance. The old binary cannot acquire the new channel selector through remote metadata alone.

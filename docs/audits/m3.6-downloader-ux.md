# M3.6 Media Downloader UX and One-Click Engine Updates

Date: 2026-11-01

## Scope

This milestone keeps the downloader local-first and preserves version `0.9.0`. It changes the operator workflow without adding a public release or an automatic app updater.

## Downloader

- URL entry is multiline. Blank lines are ignored and duplicate URLs are removed before analysis.
- Each URL is analyzed independently. A failed URL is shown beside successful video, playlist, or gallery results instead of blocking the rest.
- Controls are split into format and quality. MP4, best original, WebM, MP3, and M4A map to real backend requests; quality choices come from analyzed metadata.
- Playlist and gallery items use explicit selection with bounded rendering and thumbnails. Downloads enter a persistent queue as independent jobs.
- The queue is the single source of download status. It shows state, progress, bytes, selected output, cancellation, retry, open-file, and show-folder actions.
- Parallel jobs are capped at four. Fragment connections are capped at sixteen and map to yt-dlp `--concurrent-fragments`.
- Download progress carries a job ID and is coalesced in the UI at 100 ms so one active job does not repaint unrelated queue items.
- Destination folders are persisted locally as a preference and remain user-selected; backend output naming keeps `--no-overwrites`.

## Engine updates

- About → Media Engines shows installed and available versions, Check, Update, and Restore previous controls.
- Update downloads re-read the configured manifest, verify its Ed25519 signature, require an exact asset match, derive the allowed host from that verified asset, and then verify checksum/size before install.
- Active media jobs defer engine installation. Rollback and update use the existing managed runtime, atomic activation, health check, and rollback path.
- Production/live update remains unavailable when `ND_ENABLE_ENGINE_UPDATES`, `ND_ENGINE_UPDATE_PUBLIC_KEY`, and a trusted manifest are not configured.

## Validation

Focused UX tests cover URL parsing, safe concurrency bounds, playlist index normalization, and the existing media queue tests. Full validation is recorded in the M3.6 handoff.

# M3.2 gallery runtime and download reliability audit

Audit date: 2026-11-01. Branch: `dev`.

## Runtime status

- The existing macOS FFmpeg/FFprobe and yt-dlp bundle remains unchanged.
- A controlled PyInstaller build path is implemented in
  `scripts/build-gallery-runtime.mjs`. It requires an explicit gallery-dl
  1.32.19 source checkout and an externally managed Python/PyInstaller
  environment; it never installs packages or downloads source implicitly.
- The build records source commit/archive hash, Python/PyInstaller versions,
  target architecture and artifact SHA-256. No generated macOS gallery-dl
  artifact was produced on the development Mac because PyInstaller and a
  verified source/dependency lock were not available.
- Windows x64 continues to use the approved official raw binary record in
  `scripts/runtime-sources.json`; final installer readiness remains blocked by
  the broader Windows FFmpeg/yt-dlp/bgutil approvals.

## Reliability changes

- Persistent queue storage now accepts the previous array schema and the
  versioned envelope schema. Invalid entries are dropped safely.
- Jobs found in `analyzing`, `downloading` or `processing` on startup become
  `Interrupted — ready to retry`; they are never auto-started or shown as
  active without a live process.
- Download subprocesses receive a unique queue job identity. Cancellation is
  ignored for unrelated jobs, uses process groups on Unix, `taskkill /T /F` on
  Windows, waits for reaping, and does not delete user files.
- yt-dlp progress uses a structured progress template with optional bytes and
  total bytes. gallery-dl emits count-based progress only when recognizable
  file-completion lines are available; otherwise it remains indeterminate.
- Preview rendering is bounded to 50 visible rows at a time, while metadata
  retrieval remains capped at 200 entries.

## Control boundary

Rust validates the initial URL and browser option, constructs argument arrays,
resolves engines through the centralized managed/bundled/development resolver,
and delegates extractor/network behavior to yt-dlp or gallery-dl. Redirects,
DNS resolution and extractor-fetched URLs are not fully sandboxed; this is an
explicit remaining SSRF boundary rather than a claimed complete isolation.

## Verification

- Local gallery-dl metadata preview: pass with a public Wikipedia page using
  `--simulate` and a bounded range.
- Local yt-dlp metadata preview: pass with a public YouTube fixture.
- Packaged macOS gallery-dl invocation: not executed because no self-contained
  gallery executable exists in the bundle.
- Deterministic queue, Rust, frontend build and runtime checks are recorded in
  the M3.2 handoff report.

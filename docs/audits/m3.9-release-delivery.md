# M3.9 v0.9.0 release delivery audit

Date: 2026-11-01

## Implemented

- Release CI now emits exact per-target installer copies:
  - `ND-Image-Converter_0.9.0_macos-arm64.dmg`
  - `ND-Image-Converter_0.9.0_macos-x64.dmg`
  - `ND-Image-Converter_0.9.0_windows-x64-setup.exe`
- Each target bundle keeps its complete verified media-engine runtime and produces `SHA256SUMS.txt`.
- A manual release job can assemble a clearly labeled v0.9.0 pre-release only after all three native jobs pass. Stable publication is intentionally rejected while signing gates are open.
- The in-app checker uses the native Tauri target command, semantic release comparison, stable-release filtering, exact installer names, release notes and a release-page fallback.
- A self-contained website landing page package supports OS recommendation, manual selection and no automatic download.

## Current external state

- No `v0.9.0` tag or GitHub Release existed at audit time; latest stable release was `v0.8.4`.
- The existing website endpoint redirected to the combined v0.8.4 ZIP. WordPress/hosting access was not available, so the endpoint was not modified.
- Tauri updater plugin, updater keypair and signed updater artifacts are not present. v0.9.0 remains browser-assisted installer download only.
- macOS packages are ad-hoc/unsigned and not notarized; Windows Authenticode is not configured.

## Explicit gates

The `publish_release` workflow input defaults to false and stable publication fails closed. Before any pre-release publication, native CI must produce and verify all three installer assets, checksums, runtime bundles and smoke tests. Website asset URLs must be copied from the actual GitHub Release API response only after publication.

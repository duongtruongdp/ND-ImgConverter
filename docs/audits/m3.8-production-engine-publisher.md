# M3.8 Production Engine Publisher and End-to-End Acceptance

Date: 2026-11-01

## Implemented

- Schema 2 manifests authenticate channel, revision, publication/expiry bounds, package identity and all artifact metadata.
- The client requires a configured channel and key ID, rejects revoked keys, rejects stale manifest revisions, blocks engine version downgrades, and caches only verified manifests for remote artifact installation.
- Remote manifest retrieval is HTTPS-only, host-allowlisted, redirect-bounded and size-limited. The existing asset downloader keeps exact host, size, SHA-256, platform, architecture and health checks.
- `scripts/prepare-engine-manifest.mjs` binds real artifacts to approved `runtime-sources.json` records. `scripts/sign-engine-manifest.mjs` signs the exact Rust canonical bytes.
- `.github/workflows/publish-engine-update.yml` is manual and prepare-only. It has read-only contents permission and deliberately rejects production publication from the application repository.
- Active media jobs are enforced by the backend during install; concurrent engine downloads are serialized and duplicate in-flight downloads are rejected.

## Staging/production boundary

Staging and production are separate through channel configuration, key ID/public key, manifest host and manifest endpoint. This repository has no production private key and does not publish a feed. The proposed dedicated repository is documented in `docs/runtime/engine-distribution-repository.md` but has not been created.

## Acceptance status

- Local canonical publisher tests: passed.
- Local manifest builder against authentic macOS arm64 runtime artifacts: passed.
- Authentic local yt-dlp managed activation/version reporting/rollback: passed.
- Real HTTPS signed-manifest retrieval: blocked; no authorized staging HTTPS host is available.
- Real artifact download from hosted immutable URL: blocked by the same missing host.
- Real media operation after engine update and after rollback: not executed; `--version` health checks are not counted as media acceptance.
- macOS arm64 packaged update: not executed.
- macOS Intel update: not executed.
- Windows x64 update: not executed.

## Remaining trust and release gates

Production requires a dedicated engine repository or approved static host, protected staging/production signing environments, public-key registration in a signed app build, revocation policy, native OS signing/notarization, license/source compliance publication, and native cross-platform acceptance.
